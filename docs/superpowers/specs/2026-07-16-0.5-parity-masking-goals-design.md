# 0.5 — Parity release: discrete action masking + goal conditioning

**Date:** 2026-07-16
**Status:** Design approved; ready for implementation planning.
**Target release:** 0.5

## Summary

0.4.0 shipped a large feature batch (182 commits) and closed essentially all of the
godot_rl_agents parity gaps — the gap analysis is now overwhelmingly ✅ Done / **Advantage**, and
the Unity ML-Agents flagships that had trained deliverables (3DBall, GridWorld, self-play,
curriculum, MA-POCA, attention/BufferSensor, locomotion) are done too.

Two genuine Unity ML-Agents parity gaps remain, both verified absent in the codebase:

1. **Discrete action masking** — per-decision invalid-action masking (Unity's
   `WriteDiscreteActionMask`). Neither godot_rl nor this project has it.
2. **Goal-conditioned observations** — a distinct goal-signal obs channel + a policy that pursues
   different goals at runtime (Unity's goal signals).

0.5 closes both, each as a genuine **trained deliverable** with regressions. Masking is the
flagship and also a moat (native masked inference at deploy — no ONNX/.NET runtime does per-step
masking without custom glue). Both features run on every deploy target including web/WASM.

## Non-goals (explicit)

- **Hypernetwork goal conditioning** (Unity's advanced goal-signal feature) — a large
  net-architecture + ncnn-export lift; deferred.
- **Continuous-action masking** — masking is discrete/multi-discrete only by definition; continuous
  actions are unaffected.
- **Unity's exact YAML trainer-config surface** — out of scope.
- **The upstream #377 contribution** (terminated/truncated → godot_rl_agents) — a separate track.

## Milestone 1 — Discrete action masking (full stack)

Masking spans the whole pipeline: game emits a mask → additive wire field → trainer respects it →
deploy applies it at ncnn inference → trained example.

### Wire protocol (additive, backward-compatible)

- New step-message field **`action_mask`**: one entry per training agent, keyed by discrete action
  key, e.g. `{"move": [1, 1, 0, 1, 1]}` (0 = invalid, 1 = valid). Absent → all actions valid.
- Stock godot_rl ignores unknown keys, so `done` / obs / reward semantics are unchanged — the same
  additive pattern proven by `truncated` (#12) and the per-agent `info` field.
- The agent supplies the mask via a new duck-typed **`get_action_mask() -> Dictionary`** (default
  `{}` = no masking), collected by the Sync exactly like `_get_info_from_agents()`. Agents that
  don't implement it report `{}` (defensive duck-typing, like `get_truncated`).
- Multi-discrete: one array per discrete key. Continuous keys are never present in the mask.

### Deploy / core (the moat piece)

- `NcnnControllerCore.choose_and_apply_action()` reads the agent's `get_action_mask()` at inference
  and applies it **before** argmax / stochastic sampling.
- `ActionDecode.decode_actions()` gains an `action_mask` parameter. For each discrete key, the
  masked logits are set to a large negative sentinel (−∞ semantics; a finite fp16-safe value like
  `-6e4`, consistent with the attention-encoder mask convention) before argmax/softmax-sample, so a
  masked action can never be selected.
- Pure helper **`apply_action_mask(logits, mask) -> masked_logits`** — unit-tested in isolation.
- **All-masked edge case:** if a branch has zero valid actions, `push_error` and fall back to the
  unmasked argmax (never crash). Unity contractually requires ≥1 valid action; we fail loud but
  keep producing a decision.
- The deploy net is **shape-unchanged** — still obs → logits. Masking is applied on top game-side,
  so the ncnn graph and the export pipeline are untouched.

### Training

- A **MaskablePPO** path (sb3-contrib — already an opt-in dependency from #378's RecurrentPPO;
  MaskablePPO ships in the same `sb3-contrib` package, so no new dependency).
- A thin **masking-aware env wrapper** surfaces the wire `action_mask` through the
  `action_masks()` method MaskablePPO calls each step; MaskablePPO sets invalid logits to −∞ before
  the categorical, so the policy learns under the mask.
- The exported actor is the same obs→logits MLP; export to ncnn is the existing pipeline. Masking is
  re-applied game-side at deploy (see above), so train-time and deploy-time masking agree.

### Example — masked GridWorld

- Extend the existing GridWorld (#48): the agent emits `get_action_mask()` that masks **off-grid
  moves** (e.g. cannot move up from the top row). Optionally also mask moving into a known pit.
- Ship a **trained masked net** + a **behavioral regression asserting the deployed net NEVER
  selects a masked action** over N decisions (the load-bearing proof), plus a golden-inference
  fixture.

### Tests (M1)

- Unit: `apply_action_mask` (masked logits → −∞ → argmax/sample only over valid; all-masked
  fallback).
- Wire: the protocol test asserts `action_mask` reaches the step message (additive; absent →
  omitted/empty is tolerated by the consumer).
- Deploy: behavioral regression — masked net never picks an invalid action across N steps; golden
  fixture for byte-stable masked argmax.
- Trainer: guarded MaskablePPO GridWorld smoke (asserts the ncnn artifact is produced; artifact
  presence implies the masked training + export path ran).

## Milestone 2 — Goal conditioning (minimal-but-real)

### GoalSensor

- A dimension-agnostic **`GoalSensor`** that emits the *current goal* as a distinct obs channel —
  duck-typed (`get_observation()` + `obs_size()`), auto-discovered by `collect_sensors()` like every
  other sensor.
- The game sets `current_goal`; the sensor encodes it (a one-hot goal id, or a small goal vector).
  This is the "what am I trying to do this episode" signal, separate from perception sensors.
- Pure encoding helper, unit-tested.

### Example — "GoToGoal"

- Several targets with distinct colors/ids. Each episode, one is signaled as *the* goal via the
  GoalSensor one-hot. One policy must reach the **signaled** target and ignore the others.
- Trained with **stock PPO** (the goal is just part of obs — no new trainer), exported to ncnn via
  the existing pipeline.

### The proof (mirrors the memory-chase ablation, #378)

- Behavioral regression: the deployed net reaches the signaled goal across ≥K *different* goals in a
  run.
- **Goal-blind control:** the same net with its goal channel zeroed cannot beat chance — proving the
  goal signal is load-bearing, not incidental.

### Tests (M2)

- Unit: GoalSensor encoding (goal id → obs channel; `obs_size()` contract).
- Deploy: multi-goal behavioral regression (reaches signaled goal for ≥K goals) + goal-blind
  ablation regression.
- Trainer: guarded GoToGoal PPO smoke.

## Cross-cutting

- **Sequencing:** M1 (masking) → M2 (goals). Independent, so they compose without coupling.
- **Testing bar:** full `./test/run_tests.sh` green + CI green on Godot 4.5 and 4.6, per the repo
  convention. New pure helpers unit-tested; new deploy features have behavioral regressions with
  cross-machine headroom (like the existing ncnn near-tie argmax gates).
- **Docs (same change):** README example bullets; CLAUDE.md key-commands (`train_gridworld_masked.sh`,
  the GoToGoal trainer) + the sensors/moat lines; the sensors guide gains GoalSensor; a new
  action-masking guide/section; the gap-analysis rows for masking + goals flip to
  **Advantage/parity**; both examples added to the demo launcher.
- **Definition of done:** two trained nets shipped, all regressions + CI green, docs updated, both
  examples runnable from the launcher → then cut **0.5** (bump `plugin.cfg`, tag `v0.5.0`; the
  release runbook in `docs/dev/RELEASING.md` handles the rest).
- **Moat callouts (lead with these in docs):** native masked inference at deploy; both features run
  on web/WASM/console/mobile where an ONNX/.NET pipeline can't.

## Open questions

None blocking. The MaskablePPO env-wrapper seam (how `action_masks()` is surfaced from the wire to
sb3-contrib) is the one implementation detail to nail down first in the plan, since it drives the
masking-aware training path.
